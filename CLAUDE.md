# Loco: Hinweise für die Arbeit im Repo

- Das Spiel heisst **Loco**. Die Bahnlinie, die man darin baut, heisst in der Fiktion weiterhin «Linie Null»; das ist kein Überbleibsel, sondern Absicht.
- Sprache im Repo ist Deutsch (Schweiz): «ss» statt «ß», Guillemets «…». Bezeichner im Code sind kurze ASCII-IDs wie in `docs/konzept.md` (zum Beispiel `eisenbarren`, `bp_stahl`).
- `docs/konzept.md` ist die Referenz für Spielregeln, Zahlen und Umfang. Wer im Code davon abweicht, führt das Konzept nach.
- Befehle: `npm install`, `npm run dev`, `npm run check` (svelte-check), `npm test` (Vitest), `npm run build`.
- Vor jedem Push: `npm run check && npm test && npm run build` müssen grün sein. Die CI führt dieselben drei Schritte aus.
- Architektur: `src/engine` ist reine Spiellogik ohne DOM, Einstieg `tick(state, dt)`. `src/ui` ist Svelte 5 mit Runes. Zahlen fürs Balancing liegen in `src/engine/balance.ts` und in `src/engine/data/`.
- Wagen und Maschinen: Von jedem Wagentyp hängt genau ein Wagen im Zug (`buildWagon` lehnt einen zweiten mit `wagen_schon_da` ab). Der Auftrag sitzt an der Maschine (`WagonState.machines`), nicht am Wagen: `buildMachine`, `removeMachine`, `setMachineRecipe`, `setMachineResource`. Plätze je Wagen liefert `machineSlots(state)` aus Grundwert, Lok und Forschung. Die n-te Maschine kostet das n-fache des Grundpreises (`machineBuildCost`). Die Kurbel sitzt am Wagen und treibt alle Erntemaschinen darin. `pauseMachine` nimmt nur den Auftrag weg, die Maschine bleibt bezahlt stehen; `removeMachine` baut sie aus und steht in der Oberfläche nur aufgeklappt und mit Rückfrage. Was eine Maschine pro Minute liefert, rechnet `machineRatePerMinute`: null, sobald `machineCanRun` nein sagt (ohne Auftrag, ohne Kurbel, volles Ausgabelager). Die Zahl steht auf der Wagenkarte je Ware und im Wagen je Maschine. Nur Angebote bleiben Sollwerte: die Rezeptauswahl im Wagen und die Rezeptliste der Werkstatt. Den Saldo je Ware fürs Lager liefert `flowPerMinute(state)`; `game.rates` ist ein `$derived` darauf, also der Stand von jetzt und kein gemessener Durchschnitt.
- Forschung: `state.techs` hat neben `current` eine `queue`. `startResearch` bezahlt sofort und reiht ein, wenn schon etwas läuft; `cancelQueuedResearch` nimmt eine wartende Forschung samt allem, was auf ihr aufbaut, wieder heraus und erstattet die Blaupausen. `canResearch` lässt Voraussetzungen gelten, die selbst in der Warteschlange stehen (`plannedTechs`, `isTechPlannable`); Biome und Projekte müssen erfüllt sein. `tickResearch` zieht die nächste sofort nach.
- Jede Bauphase aus Abschnitt 15 des Konzepts ist ein eigener Pull Request mit Squash-Merge.
- Balancing-Messlatte: `npx vitest run src/engine/autoplay.test.ts` spielt den ersten Stand mit dem Autospieler durch und druckt den Zeitplan. Änderungen an Zahlen gegen diesen Zeitplan prüfen.
- Oberfläche: `src/ui/game.svelte.ts` hält den Spielzustand als `$state` und treibt die Engine mit festem Zeitschritt. Komponenten liegen in `src/ui/components`, Texte für die Oberfläche in `src/ui/labels.ts`. Aktionen laufen über `game.run(...)`, das Fehler als Toast zeigt.
- Smoke-Test im Browser: `npm run build && npx vite preview --port 4173 &` und dann `npm run smoke` (Chromium unter `CHROMIUM_PATH`, Standard `/opt/pw-browsers/chromium`). Prüft Ernte, Werkbank, Bildschirme und den Spielstand nach einem Reload.
- Rückkehr: `game.boot()` rechnet die Abwesenheit mit `simulateOffline` nach, sobald sie eine Minute übersteigt, zeigt dabei den Rückkehr-Bildschirm und danach den Bericht. Der Spielstand merkt sich die Wanduhr in `lastSavedAt`.
- Bühne: `src/ui/components/Stage.svelte` legt den Zug als HTML über die SVG-Landschaft (`Landscape.svelte`), damit die Wagen antippbar und scrollbar bleiben. Farbstimmungen und das deterministische Streuen stehen in `src/ui/stage/scenery.ts`. Meilensteine erkennt der Spielstore aus neuen Fahrtenbuch-Einträgen; was in der Abwesenheit geschah, wird nicht gefeiert, das steht im Rückkehr-Bericht.
- Glyphen: Jede Ware braucht eine Form in `src/ui/components/ItemIcon.svelte` und einen Eintrag in `src/ui/glyphs.ts`. Fehlt einer, schlägt der Test in `src/ui/labels.test.ts` an.
- Cloud: `src/cloud` kapselt Firebase. Das SDK wird erst geladen, wenn jemand anmeldet oder schon angemeldet war, damit das Hauptbundle klein bleibt. Der Smoke-Test prüft, dass ohne Konto keine Anfrage an Firebase rausgeht.
- Firestore-Regeln: `firestore.rules` ändern, Test in `tests/firestore.rules.test.ts` ergänzen, `npm run test:rules` lokal laufen lassen. Die GitHub Action «Firestore-Regeln» prüft und veröffentlicht sie beim Merge auf main. Einrichtung und Hintergrund stehen in `docs/firebase.md`.
- Herstellungsketten: `src/engine/craft.ts` plant, was für ein Rezept nötig ist (`planCraft`), und `queueCraftChain` reiht Vorstufen und Ziel ein. `ingredientsOf` liefert Bedarf, Bestand und Fehlmenge für die Anzeige, `outputsOf` Ausbeute, Bestand und volles Lager des Ergebnisses. Die Oberfläche zeigt Rezepte als Fluss über `RecipeFlow.svelte`, einzelne Waren über `ItemChip.svelte`: Icon, klein der Name (`showName`), darunter der Bestand. Nur die knappen Stellen mit `size="s"` setzen `showNames={false}`.
- App-Gerüst: `.app` in `App.svelte` füllt den Viewport, Kopf und Leiste stehen fest, dazwischen scrollt jeder Bildschirm selbst über `.scrollbereich` oder eigenes Flex-Layout. Panels bekommen also keinen eigenen Seitenscroll mehr.
- Zug-Bildschirm: Die Bühne bleibt immer sichtbar, nichts legt sich darüber. Wagen-Detail (`WagonDetail.svelte`) und Wagenbau (`BuildPanel.svelte`) klappen in der Liste auf, gesteuert über `game.detail` (`DetailKind`). Ein Bottom Sheet gibt es nicht mehr.
- Meldungen, die mit dem Spielstand kommen und gehen, bekommen die globale Klasse `.meldung` und werden auch leer gerendert. Ihr Platz bleibt so reserviert, und die Liste springt nicht unter dem Finger weg.
- Werkstatt-Aufbau: Eigener Bildschirm in der Leiste unten, kein Wagen und kein Sheet. Tender und Werkbank stehen fest, nur `.liste` scrollt. Der Werkbank-Bereich hat eine feste Höhe und `flex: none`. Beides ist Absicht: Sonst springt die Rezeptliste, sobald ein Auftrag dazukommt, und der Knopf rutscht unter dem Finger weg. Der Smoke-Test prüft das.
